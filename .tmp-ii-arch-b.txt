19. End-to-End Execution Flow
A human, service, or authorized agent delegates a goal to a persistent Agent Kernel / Intelligence Principal.
Connector resolves AgentID, issuer, Agent Contract, continuity state, delegated authority, and current runtime measurements.
The requested LLM or other intelligence implementation presents itself to N4. It is not yet an executable agent.
N4 performs an intelligence handshake: model/provider/runtime identity where available, provenance, adapter identity, declared capabilities, observed/attested capabilities, context/state behavior, tool semantics, locality, trust evidence, and policy compatibility.
N4 produces an Intelligence Profile and either rejects the model, admits it in a restricted tier, or binds it as an intelligence parameter of the Agent Kernel.
The admitted intelligence reasons over N4-mediated context. Kernel facts, policy, memory, untrusted data, instructions, and tool results remain structurally distinguishable even if the model sees them semantically together.
N4 normalizes the result into a Cognitive Proposal Object (CPO). Provider-specific tool calls are not direct machine authority.
QPR evaluates the CPO against AgentID, contract, delegation, provenance, continuity, runtime integrity, current state, resources, and policy.
If valid, QPR issues a short-lived execution quantum scoped to one action/resource/time/state. If invalid, cognition remains non-executable.
DockLock maps the quantum to actual process/filesystem/network/syscall/device/secret/resource controls and brokers the operation.
The Linux kernel and hardware perform the machine effect under constrained resources.
WitnessCTL collects runtime/node/hardware evidence; TraceTram links model cognition -> CPO -> quantum -> tool/process/syscall/object effect.
A signed receipt records AgentID, IntelligenceID/N4 profile, contract, CPO/intent, execution quantum, runtime/machine evidence, effect, and prior receipt hash.
If the model is substituted, degraded, compromised, or unavailable, N4 can revoke or requalify the intelligence parameter without silently changing the Agent Kernel identity or inherited authority.

25. Category Definition and Positioning
Connector should not be reduced to an AI orchestration layer or a secure container platform. The category-level thesis is broader:
Connector is building an identity, authority and forensic execution layer that allows operating systems, networks, hardware and services to treat autonomous intelligence as a verifiable computational principal.
A concise set of product statements follows:
Containers isolate software. Connector aims to make autonomous intelligence itself an attributable execution principal.
The model may control reasoning; Connector controls the boundary between reasoning and reality.

Execution begins with identity and authority and ends with evidence.

27.6 Two-gate execution semantics
Gate 1 — N4 asks: May this intelligence participate in this Agent Kernel, under which capability/trust profile, and how must its cognition be interpreted?
Gate 2 — QPR asks: May this specific normalized cognitive proposal become a bounded real-world authority under the AgentID, contract, continuity state, resource state, and delegation chain?
Enforcement — DockLock asks: How is the approved execution quantum translated into actual process, syscall, filesystem, network, device, secret, and resource restrictions?
This makes the core path: untrusted intelligence -> N4-qualified cognition -> CPO -> QPR-bounded authority -> DockLock-enforced computation -> witnessed evidence. There is intentionally no supported Connector path of LLM -> shell or LLM -> privileged tool.

27.8 N4 Kernel invariants
Model independence — no specific model/provider defines the Agent Principal.
Kernel sovereignty — identity, contract, durable state, continuity, delegation, authority root, and evidence remain outside probabilistic model control.
