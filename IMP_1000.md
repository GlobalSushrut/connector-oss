# IMP-1000 — Connector OS as a Tool: What It Can Do

**Document purpose:** One practical report for operators and builders — what Connector OS is as a *tool*, what it can do today, where forensics sit, and how future workflows should plug in without rebuilding storage or evidence kernels.

**Authority:** Constitutional substrate ([docs/00-constitutional-preamble.md](docs/00-constitutional-preamble.md)), [docs/architecture/substrate-map.md](docs/architecture/substrate-map.md), live code under `platform/`, `oss/vac/`, `plugins/`.

**Honesty rule:** Capabilities below mark **shipped**, **partial**, or **planned**. Do not treat planned items as product claims.

---

## 1. One-line product

Connector OS is a **sovereign operating substrate for distributed intelligence**: one installable node that gives agents identity, admission, memory, isolation, protocols, custody, and usage metering — with TraceTramp / WitnessCtl / DevGuard as **institutions above** the kernel, not co-equal kernels.

## 3. Institutions vs kernel (how the tool is shaped)

```text
                    ┌─────────────────────────────────────┐
                    │  Workflows (institutions)             │
                    │  TraceTramp · WitnessCtl · DevGuard   │
                    │  future WFs = domain UX + policy      │
                    └─────────────────┬───────────────────┘
                                      │ compose contracts
                    ┌─────────────────▼───────────────────┐
                    │  Substrate (kernel + connector-trust) │
                    │  Identity · Admission · Memory · Cage │
                    │  Causality · Custody · Usage meters   │
                    │  (+ CFNI / Moment / ArtifactLog plan) │
                    └─────────────────────────────────────┘
```

**Rule for builders:** new workflows **compose** shared envelopes; they do **not** mint a new identity system, receipt chain, or memory database as source of truth.

## 4. Forensics today — what works

1. **Control forensics (TraceTramp)** — why a request was allowed/blocked; decision trees; handoff to WitnessCtl by `trace_id` / `request_id`.
2. **Custody forensics (WitnessCtl)** — what crossed the wire (hashes + previews); HMAC receipt chain; seal; compliance overlays; DI middle export.
3. **Kernel forensics** — audit entries on syscalls; proof/books surfaces; Vector Box for memory inspection.
4. **Joint path** — TT handoff rows folded into `di_audit_middle` with captures.

Together they answer: *who asked → what policy said → what was observed → what receipt chain claims.*

---

## 5. Forensics problems (why future WFs struggle)

| Problem | Effect |
|---|---|
| **Own Postgres per workflow** | Every new WF reinvents storage; ops and joins explode |
| **Soft correlation** | Header IDs, not cryptographic flow identity — bypass breaks forensics |
| **Security via intended routing** | If traffic skips TT/WC, evidence disappears (egress may still block) |
| **Asymmetric bodies** | Hashes/previews vs full decision trees — heavy or incomplete |
| **Fake cost in evidence UIs** | Hard-coded $ / stream $0 trains distrust |
| **Local sessions** | WFs re-mint identity instead of `PrincipalContextV2` |
| **Fail-open gaps** | Connector outage / async firewall weaken “always evidenced” |
| **Hash-link ≠ keyed custody** | Kernel audit honesty still maturing |
| **Knot / memory durability gaps** | Graph/moments not always restart-stable |
| **Admission not universal** | Some effects escape the forensic front door |

These are the blockers to “building future workflows easily.”

## 6. Placement that makes future workflows easy

### 6.1 Forensic substrate placement (target)

```text
connector-trust
  PrincipalContextV2
  AdmissionTicketV2
  CausalEnvelopeV2
  CustodyReceiptV2
  DiAuditMiddleEvent
  MemoryVectorBox
  ForensicFlowIdentityV2   (CFNI — gateway + outbound proxies)
  MomentManifestV2 + UsageEventV2 + ArtifactLogRecordV2 (kernel append paths)
        │
        ▼
Kernel write path (one ArtifactLog / moment commit)
        │
        ├── TraceTramp     = control projection + enforcement UX
        ├── WitnessCtl     = custody / compliance / export UX
        ├── Books          = usage projection (real meters)
        └── Future WF      = domain filter + UI on same envelopes
```

### 6.2 Builder contract for a new workflow

1. **Authenticate** with platform principal — do not invent a parallel user DB as trust root.  
2. **Admit** before effects — attach `AdmissionTicketV2`.  
3. **Emit** `CausalEnvelopeV2` / DI middle events (or call kernel helpers that do).  
4. **Meter** only observed usage (`provider_api` / peer receipt) on the shared UsageEvent path.  
5. **Store** fat multimodal bytes in Object Fabric; keep moment skeleton + CIDs.  
6. **Project** into your Postgres **only as cache** — rebuildable from the log.  
7. **Export** via DI middle / custody APIs — do not invent a third receipt HMAC format unless extending `CustodyReceiptV2`.

### 6.3 What “easy” means operationally

- One mental model: **moment + identity + admission + usage + custody**.  
- One correlation: CFNI / moment_id (planned) instead of hoping headers match.  
- One storage doctrine: **log + CAS + projections** — not N databases of truth.  
- One honesty language: verified only after recompute; unavailable ≠ zero.
