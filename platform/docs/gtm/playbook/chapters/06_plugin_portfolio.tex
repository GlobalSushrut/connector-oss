\chapter{Plugin Portfolio --- All Nine Apps}

\section{DevGuard \statusship}

\textbf{Tagline:} Policy enforcement for every file, command, and secret your agent touches.

\begin{itemize}
  \item \textbf{Problem:} Coding agents can run shell commands, read secrets, and modify repos without a single enforcement point.
  \item \textbf{What it does:} Cage mode, git hooks, exec hardening, live dashboard, approval flows for blocked actions.
  \item \textbf{Buyer:} VP Engineering, security-minded CTO, platform team supporting dev tools.
  \item \textbf{Not a substitute for:} API-level witness (pair with WitnessCtl for full audit story).
\end{itemize}

\section{TraceTramp \statusship}

\textbf{Tagline:} Full execution graph for every agent call---language agnostic, proxy at the ingress.

\begin{itemize}
  \item \textbf{Problem:} Traffic bypasses observability; policies are inconsistent across services.
  \item \textbf{What it does:} Data plane proxy (default \textbf{Control} pipeline = enforce + observe), management plane for tenants/policies/budgets, evidence plane for exports.
  \item \textbf{Buyer:} Platform engineer, ML ops lead.
  \item \textbf{Pairs with:} WitnessCtl (handoff for SIEM / audit alignment).
\end{itemize}

\section{WitnessCtl \statusship}

\textbf{Tagline:} Cryptographic audit receipts for every agent action---tamper-evident, export-ready.

\begin{itemize}
  \item \textbf{Problem:} Logs are not defensible; auditors want artifacts.
  \item \textbf{What it does:} Session capture, decision digest (firewall, kernel snapshot, TraceTramp hints), export JSON/CSV/Markdown/HTML/PDF.
  \item \textbf{Buyer:} CISO, compliance lead, risk officer.
  \item \textbf{Demo moment:} Export HTML $\rightarrow$ Print to PDF for auditor walkthrough.
\end{itemize}

\section{LedgerLens \statusship}

\textbf{Tagline:} Real-time cost attribution per agent, team, and model---with hard budget gates.

\begin{itemize}
  \item \textbf{Problem:} ``We spent \$47K on GPT-4'' with no owner or lever.
  \item \textbf{What it does:} Executive dashboard, chargeback pivots, anomaly alerts, budget policies (alert, downgrade, hard-stop, queue), CFO export package.
  \item \textbf{Buyer:} CTO, FinOps, CFO office.
  \item \textbf{Pairs with:} TraceTramp (traffic metering) for accurate attribution.
\end{itemize}

\section{Conductor \statusplan}

\textbf{Tagline:} Multi-agent orchestration without adopting another framework.

\begin{itemize}
  \item \textbf{Problem:} Hand-rolled orchestration lacks runtime policy and recovery.
  \item \textbf{Future value:} Declarative pipelines with kernel-enforced caps---OS-level orchestration, not just DAG scripts.
  \item \textbf{Buyer:} Platform team running 10+ cooperating agents.
\end{itemize}

\section{AgentLoop \statusplan}

\textbf{Tagline:} Agent lifecycle management---spawn, monitor, suspend, recover.

\begin{itemize}
  \item \textbf{Problem:} No standard lifecycle for long-running agents at scale.
  \item \textbf{Future value:} DNS-style agent addressing, mesh routing, workers, observability tiers (per product docs).
  \item \textbf{Buyer:} Infrastructure lead treating agents like microservices.
\end{itemize}

\section{AgentPassport \statusplan}

\textbf{Tagline:} W3C DID identity for every agent.

\begin{itemize}
  \item \textbf{Problem:} Agents share API keys; no portable identity or revocation story.
  \item \textbf{Future value:} Verifiable agent identity across systems and partners.
  \item \textbf{Buyer:} Security architect, B2B platforms issuing agent credentials.
\end{itemize}

\section{Relay \statusplan}

\textbf{Tagline:} Zero-framework runtime---register an HTTP endpoint, get governance.

\begin{itemize}
  \item \textbf{Problem:} Teams want governance without rewriting to a new SDK.
  \item \textbf{Future value:} Fastest path: point base URL at Relay, see audit log, add budget lines in config.
  \item \textbf{Buyer:} Developer who needs a win in one sprint.
\end{itemize}

\section{Engram \statusplan}

\textbf{Tagline:} Enterprise memory for agents---entropy-scored, dehallucination enforced.

\begin{itemize}
  \item \textbf{Problem:} Ad-hoc RAG and chat memory are not governed or auditable.
  \item \textbf{Future value:} Memory writes chained to audit; quality scoring for grounding.
  \item \textbf{Buyer:} ML engineer, healthcare/regulated knowledge use cases.
\end{itemize}

\section{Progressive adoption narrative}

\begin{quote}
\emph{``Use one plugin or all nine. Start where it hurts---WitnessCtl for audit, LedgerLens for spend, DevGuard for coding agents---then add workflows on the same node.''}
\end{quote}

Do not promise all nine as GA in the first meeting unless the roadmap has been confirmed for that account.
