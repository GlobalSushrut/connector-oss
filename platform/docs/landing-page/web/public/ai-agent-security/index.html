The AI agent threat model

Prompt injection

Malicious instructions embedded in data sources, emails, or tool responses that redirect agent behavior. Traditional firewalls don't inspect LLM context — Connector's 5-layer content inspection does.

Tool misuse

Agents calling tools outside their intended scope, with unintended parameters, or at unintended frequency. Connector enforces tool allowlists pre-execution — calls not on the list are blocked.

Privilege escalation

Agents acquiring permissions beyond what their role requires by chaining tool calls or exploiting overly broad context. Connector's namespace isolation and capability limits prevent scope expansion.

Goal hijacking

External inputs that shift agent goals away from their intended objective. Connector's policy contracts define the boundaries of acceptable agent behavior — deviations are blocked and receipted.

Why AI agents need a different security model

  • Agents act at machine speed — human review cannot keep up without automated enforcement
  • Agents chain tool calls — one compromised step can cascade through an entire workflow
  • Agents access production systems — a misused tool creates real damage, not just a log entry
  • Agents are persistent — they maintain state across sessions, compounding exposure over time
  • Agents are trusted by default — most platforms assume agent requests are legitimate

Security controls that work at the AI execution layer

5-layer content inspection

Every prompt and tool response inspected for injection attempts, PII exposure, hallucination markers, schema violations, and intent anomalies — before the agent acts on it.

Pre-execution policy gates

Policy checks happen before tool calls execute. Violations are blocked with a denial receipt — not flagged after the fact in a SIEM.

Cryptographic evidence

Every security decision produces a tamper-evident receipt. Security incidents have complete evidence chains — not reconstructed logs.
