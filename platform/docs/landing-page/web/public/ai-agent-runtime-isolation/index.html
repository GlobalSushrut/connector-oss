AI Agent Runtime Isolation

Granted worlds. Dest-pinned dials. Default DROP.

When multiple AI agents share infrastructure, the risk is cross-agent contamination: one agent reads another's secrets, a compromised agent pivots to adjacent workloads, or multi-tenant data leaks between customer contexts. The world cage is built to fail closed on ungranted destinations. It does not claim contamination is impossible, and it is not Firecracker-by-default.

Connector is a self-hosted OS for intelligence. Three institutions are ready: DevGuard, TraceTramp, WitnessCtl. Isolation today is dest-pinned Landlock children, not Firecracker-by-default. HMAC receipts are inspectable evidence — not a sold SOC 2, HIPAA, or FedRAMP checkbox. Stop is not undo. Memory and journals stay on the node; vendor LLM HTTP may leave when a model is granted.

What the world cage is built to stop

Secret leakage

Credentials, API keys, and tokens scoped to one agent cannot be accessed by another. Secret brokering ensures agents receive only the credentials their policy authorizes.

Data contamination

Memory namespaces enforce that agents only read data their role permits. A customer-A agent cannot access customer-B data — enforced at the storage layer, not the application layer.

Lateral movement

A compromised agent cannot pivot to adjacent workloads. Capability limits define exactly what each agent can reach — and nothing else.

Context bleed

Selective context construction ensures agents only receive context relevant to their current task. Past conversations, other agents' context, and out-of-scope data are excluded before the LLM call.

How Connector implements runtime isolation

  • Identity at boot on the node. W3C DID packaging (AgentPassport) is planned, not ready
  • Namespace isolation — private (/p/), shared (/s/), and organizational (/o/) memory tiers
  • Secret broker — agents receive scoped, time-limited credentials — never raw secrets
  • Capability limits — tool access defined per agent identity, not per application role
  • Context construction — selective, policy-governed context — no full history exposure
  • Boot verification — 12-stage boot sequence ensures agent integrity before any workload runs
