1. Executive thesis & product model

Connector is an agent operating substrate: software for engineers who build and operate dynamic agents inside augmented environments. The engineer chooses the operating envelope. The agent may behave dynamically inside that envelope, but cannot silently expand or bypass it.

One-line promise. Tools + environment + constraint/isolation + monitoring + proof — with honesty and reconstructibility of consequence — not absolute security.

1.1 Five product layers

LayerWhat it isExamples in Connector
ToolsInterfaces the agent may useTalk, MCP, CNP/CONP, VAC memory, mission, AAPI effects
EnvironmentIdentity, knowledge, cognitive stateNamespaces, WorldGrant pores, DIM Zt, Knot beliefs
ConstraintWhat may not happenContracts, NF³, PATE, budgets, Landlock, MicroCell, HITL
MonitoringLive operator view without raw CoTOperator pulse, regime, Φ, denials, spend, HITL
ProofReconstructible worldlineDigests, receipts, Packet DNA, journals, forensic export

1.2 Continuum (same spine)

more dynamic / exploratory          more constrained / verified
◄──────────────────────────────────────────────────────────────►
 higher Θ, wider recall              lower Θ, HITL on R2/R3
 softer budgets                      BCR spend + trajectory caps
 T0 / V0 app gates only              Landlock → shared/dedicated MicroCell
 playground soft-fail (LAB)          fail-closed harden + START_REFUSED

Playground and production are postures of the same product, not two products. Soft must be labeled soft.

1.3 Five invariants (always)

  1. Posture honesty — Requested / Applied / Effective; LAB when critical gates off.
  2. Effect exclusivity when applied — mutating paths through ActionBinding / PATE.
  3. Engineer freedom — compose contract, grants, tier, HITL, budgets, DIM independently.
  4. Reconstructible worldline — admitted effects leave digests / receipts / exportable evidence.
  5. No cognitive self-authorization — DIM / Knot / KECS / confidence never mint Allow.

3. Authority & effect spine

Every mutating consequence is meant to pass a single conceptual admit path. Soft/playground may label LAB; harden must refuse or fail closed.

3.1 Effect exclusivity

When CONNECTOR_EFFECT_EXCLUSIVITY=1 (on under augmented env / production presets), alternate mutating paths (raw shell, ungated child spawn, CONP bypass) are closed or refused. Ungated paths are bugs to close, not features.

4. Agent isolation architecture (three layers)

Thesis: Connector isolates agents, not merely processes. Three layers are required and composed.

4.1 Engineer isolation surface

agent:
  isolation: auto                 # linux-cell | hardened-linux-cell | shared-microvm | dedicated-microvm
  isolation_risk: R2              # drives auto table only — never grants authority
  resources: default              # small | default | compute

9. Why an engineer should use it

Problems it solves

  • Agents that “just call tools” with ambient authority
  • No way to prove what was admitted vs what the model said
  • Lab demos silently treated as production-hardened
  • Isolation knobs scattered (cgroup here, prompt rules there)
  • No promote path when risk rises mid-life
  • Cognitive confidence mistaken for permission

What you gain

  • One envelope language: contract · grant · tier · budget · HITL
  • Same APIs from playground to harden
  • OS-grade lifecycle + MicroCell when you need it
  • Exportable worldline for incident / audit review
  • Explicit LAB banners when Effective is unmet
  • DIM/Knot for cognition without authority bleed
Engineer job. Choose the point on the dynamic↔constrained continuum; Connector makes that choice real, observable, and reconstructible.

12. Tool — not full security software

Connector is a governed-autonomy toolkit / agent OS substrate. It is not a replacement for enterprise GRC suites, endpoint EDR, network firewalls, physical SIL, or legal compliance programs.
What people might assumeWhat Connector actually is
“Install Connector → agents are secure”Engineer must choose and apply posture; misconfig stays soft/LAB
“We are HIPAA/SOC2 certified by Connector”Evidence/export for org mapping; optional GRC routes ≠ certification
“LLM cannot be jailbroken”Membrane gates consequence; model content attacks remain a risk class
“MicroCell = airgap”KVM boundary + semantic gates; covert channels / host compromise out of scope
“Partner HAL/SIL proven”Physical safety stays partner-attested — never claimed from lab stubs
“DIM high confidence = safe to act”Confidence never becomes Allow

12.1 Correct use of the tool

  1. Define agent contract and WorldGrants explicitly.
  2. Pick isolation profile (or auto + risk) matching blast radius.
  3. Enable augmented env / harden for production nodes.
  4. Verify Effective on hosts that claim MicroCell.
  5. Monitor via pulse; quarantine with human gate when needed.
  6. Export worldline for incidents — do not invent “compliance green.”

14. How to use (operator runbook)

14.1 Dev / playground

# soft exploration
export CONNECTOR_PLAYGROUND=1
# start connectord per BOOTSTRAP_RUNBOOK / Makefile
# inspect: GET /api/v1/substrate/status → expect LAB labels when gates off

14.2 Augmented / production posture

export CONNECTOR_AUGMENTED_ENV=1
systemctl enable --now connector-microd.service   # if MicroCell required
# pin FC/jailer/kernel/rootfs (see §5.2)
# register agent with isolation: auto|shared-microvm|dedicated-microvm
# start: POST /agents/:pid/start — expect START_REFUSED if Effective unmet

14.3 Day-2 ops

# status
curl -s $BASE/api/v1/cvr/status | jq .
curl -s $BASE/api/v1/operator/pulse | jq .

# promote
curl -s -X POST $BASE/api/v1/agents/$PID/isolation/promote \
  -H 'content-type: application/json' \
  -d '{"target":"dedicated"}'

# quarantine / stop
curl -s -X POST $BASE/api/v1/agents/$PID/quarantine
curl -s -X POST $BASE/api/v1/agents/$PID/operator-stop

# proof
curl -s $BASE/api/v1/proof/export/$PID -o worldline.json
connectorctl worldline export --agent $PID

14.4 Acceptance on a host

make cvr-soft-acceptance
make cvr-kvm-acceptance    # requires /dev/kvm + assets
# artifact: artifacts/cvr-acceptance/cvr-kvm-acceptance.json
